# 查找

> 从静态查找到动态索引——折半、树表与散列。

## 1. 基本概念

### 1.1 查找表与关键字

**定义 1.1**　**查找表**是由同一类型数据元素构成的集合。**关键字**是数据元素中可唯一标识该元素的数据项。

**定义 1.2**：
- **静态查找表**：只做查询，不改变表结构
- **动态查找表**：查找过程中可插入或删除元素

**定义 1.3**　**平均查找长度（ASL）** 是查找过程中比较次数的期望：

$$ASL = \sum_{i=1}^{n} p_i c_i$$

其中 $p_i$ 为查找第 $i$ 个元素的概率，$c_i$ 为找到它所需的比较次数。

**推论 1.1**　ASL 是衡量查找算法效率的核心指标——分成功与失败两种情形。

## 2. 线性表的查找

### 2.1 顺序查找

**算法 2.1**：从头到尾逐个比较。

**定理 2.1**：等概率下顺序查找成功的平均查找长度为 $\frac{n+1}{2}$，时间复杂度 $O(n)$。

**注意**　设置**哨兵**可省略越界判断——将待查值放入表头（或表尾）。

**推论 2.1**　顺序查找对表的有序性无要求，适用于任意线性表（含链表）。

### 2.2 折半查找

**算法 2.2**（二分查找）：要求表**有序且顺序存储**。每次取中点比较，缩小一半范围。

```
binarySearch(a, n, key):                 // 返回下标，未找到返回 -1
    low = 0; high = n - 1
    while low <= high:
        mid = (low + high) / 2
        if a[mid] == key:  return mid
        elif a[mid] < key: low = mid + 1
        else:              high = mid - 1
    return -1
```

**定理 2.2**：折半查找的时间复杂度为 $O(\log n)$，成功时的 ASL 约为 $\log_2(n + 1) - 1$。

**定理 2.3**：折半查找的判定树是平衡的，深度为 $\lfloor \log_2 n \rfloor + 1$（成功情形）。

**注意**　折半查找**不适用于链表**——无法 $O(1)$ 定位中点。

**推论 2.2**　折半查找以有序性为代价换取对数时间——静态查找表的首选。

### 2.3 分块查找

**定义 2.3**　**分块查找**把表分成若干块，块内无序、块间有序，用**索引表**记录各块最大值。

**定理 2.4**：若均匀分块，ASL 约为 $\sqrt{n} + 1$——介于顺序查找与折半查找之间。

**推论 2.3**　分块查找兼顾插入的灵活性与查找的效率。

| 查找方法 | ASL（成功） | 时间 | 前提 |
|----------|-------------|------|------|
| 顺序查找 | $\frac{n+1}{2}$ | $O(n)$ | 无 |
| 折半查找 | $\log_2(n+1) - 1$ | $O(\log n)$ | 有序 + 顺序存储 |
| 分块查找 | $\sqrt{n} + 1$ | $O(\sqrt{n})$ | 块间有序 |

## 3. 树表的查找

### 3.1 二叉排序树

**定义 3.1**　**二叉排序树（BST）** 满足：左子树所有结点关键字 < 根 < 右子树所有结点关键字，且左右子树也是 BST。

**定理 3.1**：对 BST 进行**中序遍历**得到关键字的有序序列。

**推论 3.1**　BST 的查找、插入、删除平均时间复杂度为 $O(\log n)$。

**算法 3.1**：
- **查找**：从根开始，小则向左、大则向右
- **插入**：查找失败处即为插入位置
- **删除**：分三种情形——叶子直接删；单孩子用孩子替代；双孩子用中序前驱（或后继）替代后递归删除

```
bstSearch(root, key):                    // 二叉排序树查找
    while root != NULL and root.key != key:
        root = (key < root.key) ? root.left : root.right
    return root

bstInsert(root, key):                    // 插入，返回新根
    if root == NULL:        return new Node(key)
    if key < root.key:      root.left  = bstInsert(root.left, key)
    elif key > root.key:    root.right = bstInsert(root.right, key)
    return root                          // 相等则不插入
```

**定理 3.2**：BST 的查找效率取决于树高。最好情况（平衡）为 $O(\log n)$，最坏情况（退化为单支树）为 $O(n)$。

**推论 3.2**　BST 的效率不稳定——排序序列插入会退化为链表，需引入平衡机制。

### 3.2 平衡二叉树

**定义 3.2**　**平衡二叉树（AVL 树）** 是任意结点左右子树高度差（**平衡因子**）绝对值至多为 1 的 BST。

**定理 3.3**：含 $n$ 个结点的 AVL 树高度为 $O(\log n)$，故查找、插入、删除均为 $O(\log n)$。

**算法 3.2**（旋转）：插入/删除导致失衡时，按以下四种情形旋转恢复平衡：

| 失衡类型 | 平衡因子 | 旋转 |
|----------|----------|------|
| LL | 左子树的左子树过高 | 右旋 |
| RR | 右子树的右子树过高 | 左旋 |
| LR | 左子树的右子树过高 | 先左旋后右旋 |
| RL | 右子树的左子树过高 | 先右旋后左旋 |

**推论 3.3**　AVL 树以一次（或两次）旋转、$O(1)$ 代价恢复平衡，保证对数高度。

### 3.3 红黑树

**定义 3.3**　**红黑树**是带颜色的 BST，满足：
1. 根与叶子（NIL）为黑
2. 红结点的孩子为黑
3. 从任一结点到其叶子的路径上黑结点数相同

**定理 3.4**：红黑树高度至多为 $2\log_2(n + 1)$，查找、插入、删除均为 $O(\log n)$。

**推论 3.4**　红黑树用更宽松的平衡（旋转更少）换取与 AVL 相当的高度——工程上更常被采用（如 C++ `std::map`、Java `TreeMap`）。

### 3.4 B 树与 B+ 树

**定义 3.4**　**$m$ 阶 B 树**是满足下列条件的多路平衡查找树：
1. 每个结点至多 $m$ 棵子树
2. 根至少有 2 棵子树，其余非叶结点至少有 $\lceil m/2 \rceil$ 棵子树
3. 所有叶子在同一层

**定理 3.5**：$m$ 阶 B 树的高度为 $O(\log_m n)$——通过增大分叉数降低树高。

**推论 3.5**　B 树针对**磁盘 I/O** 优化：一个结点即一次磁盘读取，高扇出使树高极低。

**定义 3.5**　**B+ 树**是所有数据存于叶子、叶子按序链接、内部结点仅作索引的 B 树变体。

**定理 3.6**：B+ 树的叶子链表支持高效**范围查询**与顺序扫描。

**推论 3.6**　数据库索引（如 MySQL InnoDB）与文件系统普遍采用 B+ 树——减少 I/O 且支持范围检索。

**注意**　B 树 vs B+ 树：B 树的数据分布在所有结点，B+ 树数据全在叶子且叶子成链。

### 3.5 Trie 树

**定义 3.6**　**Trie（前缀树/字典树）** 用树的路径表示字符串的字符，从根到某结点的路径构成一个前缀。

**定理 3.7**：Trie 的插入、查找、删除均为 $O(L)$（$L$ 为串长），与集合大小无关。

**推论 3.7**　Trie 适合字符串检索、前缀匹配、自动补全与 IP 路由。

| 树表 | 查找时间 | 特点 |
|------|----------|------|
| BST | 平均 $O(\log n)$，最坏 $O(n)$ | 简单，易退化 |
| AVL | $O(\log n)$ | 严格平衡，旋转多 |
| 红黑树 | $O(\log n)$ | 弱平衡，工程常用 |
| B/B+ 树 | $O(\log_m n)$ | 高扇出，适合外存 |
| Trie | $O(L)$ | 与集合大小无关 |

## 4. 散列表

### 4.1 散列函数

**定义 4.1**　**散列表（哈希表）** 通过**散列函数** $H(key)$ 把关键字直接映射到存储位置。

**定义 4.2**　**冲突**：$key_1 \neq key_2$ 但 $H(key_1) = H(key_2)$。

**推论 4.1**　由鸽巢原理，冲突不可避免——散列表设计围绕"减少冲突 + 处理冲突"展开。

**常见散列函数**：

| 方法 | 公式/思路 |
|------|-----------|
| 直接定址 | $H(key) = a \cdot key + b$ |
| 除留余数 | $H(key) = key \bmod p$（$p$ 取质数） |
| 数字分析 | 取关键字分布均匀的若干位 |
| 平方取中 | 取 $key^2$ 的中间几位 |
| 折叠法 | 分位数相加 |

**定理 4.1**：除留余数法中，$p$ 取不超过表长的最大质数可减少冲突。

### 4.2 冲突处理

**方法 1（开放定址法）**：探测序列寻找空位。

$$H_i = (H(key) + d_i) \bmod m$$

| 探测 | $d_i$ |
|------|-------|
| 线性探测 | $1, 2, 3, \ldots$ |
| 二次探测 | $1^2, -1^2, 2^2, -2^2, \ldots$ |
| 双重散列 | $i \cdot H_2(key)$ |

```
hashInsert(H, key):                      // 开放定址（线性探测）插入
    i = key % m
    while H[i] 已占用 and H[i].key != key:
        i = (i + 1) % m                  // 线性探测
    H[i] = key

hashSearch(H, key):
    i = key % m
    while H[i] 已占用:
        if H[i].key == key: return i
        i = (i + 1) % m
    return -1                            // 遇空位即失败
```

**注意**　开放定址会引发**聚集**（堆积），二次探测与双重散列可缓解。

**方法 2（链地址法）**：同义词存入同一链表，装填因子可大于 1。

**定理 4.2**：链地址法在装填因子为 $\alpha$ 时，成功查找的平均比较次数约为 $1 + \alpha/2$。

**推论 4.2**　链地址法无聚集问题、删除简单，是工程实现的主流（如 Java `HashMap`）。

### 4.3 装填因子与性能

**定义 4.3**　**装填因子** $\alpha = \frac{n}{m}$（元素数 / 表长）。

**定理 4.3**：散列表的平均查找长度只依赖于 $\alpha$，与 $n$ 无关——这是散列的核心优势。

**推论 4.3**　控制 $\alpha$（通常 ≤ 0.75）并在超限时**扩容再散列**，可保证平均 $O(1)$ 的查找。

**注意**　散列表的最坏情形仍为 $O(n)$（所有关键字冲突），但实际中极少发生。

## 5. 各种查找方法的比较

| 方法 | 平均时间 | 最坏时间 | 有序要求 | 适用 |
|------|----------|----------|----------|------|
| 顺序查找 | $O(n)$ | $O(n)$ | 无 | 小表、链表 |
| 折半查找 | $O(\log n)$ | $O(\log n)$ | 有序 | 静态有序表 |
| 二叉排序树 | $O(\log n)$ | $O(n)$ | 动态 | 动态表 |
| 平衡树 | $O(\log n)$ | $O(\log n)$ | 动态 | 动态 + 有序 |
| B+ 树 | $O(\log_m n)$ | $O(\log_m n)$ | 动态 | 外存索引 |
| 散列表 | $O(1)$ | $O(n)$ | 无 | 精确查找 |

**推论 5.1**　若只需精确查找且不需有序性，散列表最优；若需范围查询或有序遍历，选平衡树/B+ 树。

## 6. 应用

### 6.1 数据库与文件系统
- B+ 树实现索引，支持范围查询与顺序扫描
- 散列索引用于等值查询

### 6.2 编译与解释
- 符号表用散列表或平衡树
- 关键字识别用 Trie

### 6.3 缓存与去重
- 散列表实现缓存、去重、集合运算
- 布隆过滤器用位数组近似判存在
